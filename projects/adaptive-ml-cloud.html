Adaptive ML Cloud Platform

An elastic, API-first ML platform on AWS that replaced a legacy monolithic three-tier model.

Period2022 – present
My roleArchitect, builder
EmployerInfineon

The challenge

Move from a legacy monolithic three-tier design to a cloud-native, microservice, API-first platform that scales on demand and keeps cost under control.

What I built

  • Architected and deployed to production an ML platform on AWS that elastically auto-scales from 1 to 20 workers.
  • Turned PostgreSQL databases into production-ready ML APIs with PostgREST.
  • Served PyTorch and TensorFlow inference for audio processing and wake-word detection through FastAPI.
  • Orchestrated distributed high-performance computing with experiment tracking and serverless containers.
  • Removed Redis and SQS dependencies and introduced PostgreSQL-native vector similarity search.
  • Enabled real-time identification of potential issues so teams could maintain proactively and minimise downtime.
  • Built a closed-loop, simulator-assisted auto-optimization system that tunes the platform's own resources from live telemetry, with safe rollout and automatic rollback.

Closed-loop auto-optimization

Manual tuning and simple threshold-based autoscaling react after performance has already degraded, and they optimise one metric at a time. The platform instead runs a feedback loop that watches its own telemetry, proposes configuration changes, predicts their effect before anything is touched, and applies only the changes that are predicted to be safe.

  • Hybrid decisions: a fast rule-based controller with hysteresis and smoothed metrics handles immediate threshold breaches, while an ML optimizer trained on historical telemetry proposes longer-horizon improvements.
  • Simulate before acting: a lightweight what-if simulator estimates the effect of each candidate on latency, cost and the chance of missing a service-level objective. It is deliberately conservative, under-estimating benefits and over-estimating risks.
  • Cost versus service level: the planner ranks candidates by expected cost subject to a probabilistic service-level constraint, so cost savings never silently trade away reliability.
  • Policy and audit in the database: proposals, approvals, executions and outcomes are recorded in transactional database tables with access control, so every automated decision has a rationale and a trail from the telemetry that triggered it.
  • Safe execution: an executor re-validates each approved action against live telemetry and policy, applies it idempotently, watches the result for a defined window and rolls back automatically if metrics regress.
  • Human in the loop: the system can run in recommendation-only mode, where operators review and approve each proposed change with its rationale before it is applied.

Outcomes

  • 45 ms audio processing and sub-100 ms API responses.
  • About 95% resource utilization with 60–85% cost reduction.
  • Zero security incidents.
  • Resource decisions that are explainable and auditable, and that are checked by simulation before they are applied.
  • Two patentable inventions filed in cloud infrastructure.
